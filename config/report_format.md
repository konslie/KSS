## 2. 포트폴리오 영향도

프론트엔드는 `view_model.json`으로 포트폴리오 현황 테이블을 직접 렌더링한다. 이 Markdown 표는 fallback, JSON 변환, written report context를 위한 요약 표로 유지한다.

| 종목 | 영향도 | 핵심 이슈 | 가격 | 기관 | 외인 | 7일 | 근거 |
| --- | --- | --- | --- | --- | --- | --- | --- |

근거에는 사용된 출처명을 포함하되, 뉴스/공시가 어떤 이슈인지 1문장 안에서 짧고 구체적으로 쓴다. 예: `CNBC와 yfinance 뉴스에 AI 투자 둔화 우려와 반도체 밸류에이션 부담이 언급됐고, 당일 가격은 약세였다.`

핵심 이슈는 화면의 `primary_issue`와 유사한 짧은 표현으로 쓴다. 예: `외인 매도와 가격 약세`, `공시 확인`, `최근 종가 확인 필요`.

가격은 `종가`를 크게 볼 수 있도록 `종가<br>등락폭 (등락률)` 형식으로 쓴다. 예: `120,600원<br>+3,603원 (+3.08%)`.

기관과 외인은 국내 종목만 순매수/순매도 여부와 규모를 짧게 쓴다. 예: `순매수 101억`, `순매도 56억`. 미국/나스닥 종목은 공란으로 둔다.

## 작성 규칙

- 주요 지표 카드, 첫 화면 히어로, 포트폴리오 현황 UI, 출처 뱃지, SVG line sparkline은 HTML frontend가 `view_model.json`에서 렌더링한다.
- `final.md`는 화면의 정량 UI를 반복 설명하기보다, Executive Summary와 섹터별 해석에 집중한다.
- 섹터별 브리핑에서 “상승했다/하락했다/순매수였다” 문장을 연속으로 쓰지 않는다. 그런 사실은 표와 카드에서 이미 보이므로, 본문은 원인 후보와 영향도를 설명한다.
- 사용자 리포트에는 수집기 내부 구현 세부사항을 쓰지 않는다.
- 예: fallback, 내부 매핑, API 호출 방식, 캐시 경로, parser 방식은 report 작성 가이드라인으로만 관리한다.
- 데이터 품질에는 사용자가 판단에 참고해야 하는 실패, 누락, 미확정 ticker, 출처별 한계만 적는다.
- 가격 비교는 달력상 전날이 아니라 직전 거래일 기준으로 쓴다.
- 휴장일이 끼면 `전일 대비`라고 쓰지 말고 `직전 거래일 대비` 또는 `직전 거래일 종가`라고 쓴다.
